## 1. 定位与公理

**ACM 是"模型配置"的意图 SSOT 与投影引擎**：用户声明一套与 Agent 无关的模型意图（用哪些来源、各角色指向哪里），ACM 把它安全地投影到本机各 Coding Agent 的原生配置字段，或渲染成一次性的启动参数；改动全程可审视、可恢复。

三条公理：

- **公理 1（SSOT）**：模型**意图**的描述只有一份（`~/.acm/config.yaml`）。网关发布的**目录**（Manifest）是外部引用，在投影时实时解析、缓存、显式暴露变化——与 `${ENV}` 同构：只存引用，不拷贝值。Agent 只是投影目标。
- **公理 2（非破坏性）**：ACM 只拥有它写入的字段，不拥有整个文件。未管理内容必须语义级无损保留，注释、键序、排版按格式层保证尽力保留。
- **公理 3（可逆性）**：ACM 的每一次写入都留下可恢复的版本；可以回到上一次、任意一次、或 ACM 接管前的原始状态。默认恢复粒度是 ACM 管理的字段，不误伤 Agent 期间写入的状态。

贯穿性原则：**ACM 管理的是字段，不是文件**；一切"ACM 不知道的事"（外部修改、无法表达的设置、目录变化、上游格式变化）必须**显式暴露，绝不静默处理**。

## 2. 边界

### 2.1 判定原则

> **凡是"换了 Provider / 模型之后理应保持不变的东西"，ACM 一律不碰。**

### 2.2 管什么

- **L1 连接与凭据**：端点（按协议）、凭据引用、headers、proxy。
- **L2 模型规格**：上下文窗口、最大输出、推理与输入模态等"换模型就要跟着变"的元数据——指模型的**能力上限**（来自静态声明或网关目录），写入 Agent 描述模型的字段。Agent 自己的**用量预算**（每次请求实际用多少输入 / 输出、何时压缩，如 Claude Code 的 `CLAUDE_CODE_MAX_OUTPUT_TOKENS`、自动压缩窗口）由 Agent 或用户决定，ACM 不写。
- **L3 意图**：profile —— 默认模型、角色（reasoning / fast / subagent / review）、成员注册。
- **投影**：把 L1–L3 写入 Agent 原生字段（`use` / `apply`），或渲染为一次性启动注入（`run`）。
- **历史**：写入时保存的版本，及基于它的 `history` / `restore` / `rollback`。
- **ACM 独占的辅助文件**：ACM 自己新建并独占的文件（例如 Codex 的模型 catalog），路径须在白名单内，可整文件生成，恢复即还原或删除。与 Agent 共享的文件一律只改字段。

### 2.3 不管什么

- MCP servers、tools、skills、prompts、权限、hooks、plugins、会话与登录状态（含订阅 / OAuth 登录凭据文件与钥匙串条目：ACM 永不列为受管文件，因此恢复 ACM 的字段后 Agent 自动回到原登录方式）。
- 账号轮转 / OAuth 池 / 额度监控；本地代理 / 网关 / 请求改写（VMR 的领域）。
- Secret storage（只存 `${VAR}` 引用）。
- 常驻进程；GUI。
- Agent 的**持久化**启动包装（shell 别名、PATH 垫片、包装脚本）。

### 2.4 一次性启动注入（`acm run`）的约束

允许，但必须同时满足：不写任何 Agent 配置文件；不安装任何持久化的东西；ACM 进程最长只活到 Agent 退出；注入的值与 `use` 走同一条解析路径（引用、Manifest、角色），不允许旁路；临时文件只在 ACM 私有目录、0600、用后即删；密钥不进命令行参数。

### 2.5 铁律

1. 绝不触碰 §2.3 所列内容与 Agent 运行时状态文件。
2. 绝不写入闭源 IDE 私有数据库；没有公开、稳定、可安全修改的配置接口，就不支持该 Agent。
3. 任何新功能先过 §2.1 判定，不过即拒，无论需求来自谁。
4. 写入只落在适配器声明的路径上，由引擎强制白名单校验。
5. **不盲写**：未知或破坏性的上游结构 → 该 Agent 置 ERROR 并阻断，绝不"尽力而为"。
6. **不引入外部可执行内容**：适配器是源码内置的普通 Python 模块；不做运行时动态加载、远端描述文件或 Marketplace。
7. 反面界定（出现任一即已走偏）：变成 GUI 全家桶、写私有数据库、适配器数量成为 KPI、Core Config 堆积状态或密钥保管职责、ACM 变成常驻进程。

## 3. 核心数据模型

### 3.1 实体

```
config.yaml（意图 SSOT）
  providers ── 静态（protocol + base_url + models）或 Manifest 型（manifest 引用）
  profiles  ── default / roles / models（引用）
       │  解析：${ENV} 实时求值；Manifest 条件请求并缓存
       ▼
ResolvedTarget（每个 Agent 一份：端点、凭据引用、各角色的具体模型与协议）
       │  适配器纯函数
       ▼
Plan（字段级 ops + 投影损失告警 + 错误）  ──→ 写入引擎（唯一写盘路径）
                                        └→ 或 LaunchSpec（run 的参数 / 环境变量 / 临时文件）
```

### 3.2 引用

- 凭据：`${VAR}` 与 `${VAR:-default}` 两种，整字段替换，不支持插值与嵌套；解析失败 = 硬错误，任何写盘之前整体中止。
- 模型：裸 id（静态 provider 内全局唯一）、限定 id `provider.id`、角色 `provider@role`。
- 目录来源：`manifest: <url | file | ${VAR}>`。

### 3.3 版本历史（两个原语）

- **版本库**：内容寻址，保存受管文件在每个被 ACM 写入前后的原始字节，同内容只存一份。
- **历史记录**：只追加，ACM 每写一个文件记一行（含写前版本、写后版本、写入的字段路径）；每个文件第一次被写入前先记一条 `baseline`，其写前版本即"接管前原始版本"，**永不清理**。

其余一切——漂移检测、某次改了什么、字段恢复、整文件恢复、退出 ACM——由这两个原语推导，不维护其他状态文件（`active` 指针与 Manifest 缓存除外）。

### 3.4 数据模型不变量

1. 配置与状态分离：运行时状态只在 `~/.acm/state/`，不写回 `config.yaml`。
2. 适配器只做编译（输入已解析的目标，输出 Plan / LaunchSpec），一切磁盘写入由引擎统一执行。
3. 写入原子且防并发：全局排他写锁 + 临时文件原子替换；链接与权限保真。
4. 写前必有可恢复的版本，写后必有校验；校验失败要么不落盘，要么自动退回写前版本。
5. 非破坏性两级声明：未管理节点**语义级不变**（硬承诺，引擎每次写入断言）；注释 / 键序 / 排版按格式层金样保证（尽力）。
6. 幂等：期望值 == 当前值且无漂移 → no-op，退出码 0。
7. 敏感内容全链路防护：state 目录 0700、文件 0600，输出默认掩码，明文须 `--show-secrets`。

## 4. 命令语义

### 4.1 状态

每个 Agent 的状态：`SYNCED / OUT_OF_SYNC / DRIFTED / ERROR / UNMANAGED / NOT_DETECTED`（优先级 ERROR > DRIFTED > OUT_OF_SYNC > SYNCED）。

- `DRIFTED`：ACM 管理的字段被外部（手工、Agent 运行时、其他工具）改动，与 ACM 上次写后的值不一致。
- `OUT_OF_SYNC`：意图或目录变化，期望值与当前值不一致（含"网关目录变了"）。
- `UNMANAGED`：检测到 Agent，但不在**受管集合**中（从未写入，或用户取消勾选 / 选择"不再管理" / 执行了 `restore --baseline`）。

### 4.2 命令

```
acm init [--vmr URL]        # 扫描 Agent + 探测 VMR + 展示提案 + 确认后生成 config.yaml
acm status [AGENT]          # 各 Agent 状态、漂移明细、目录变化、投影损失摘要
acm use PROFILE [AGENT...]  # 改变激活 profile 并立即投影（不点名时先选择受管 Agent）
acm apply [AGENT...]        # 不改意图，仅按当前意图 + 最新目录重新收敛（同上）
acm history [AGENT]         # 查看历史
acm restore REF [AGENT]     # 恢复到某一次写入之后；--baseline 回到接管前；--file 整文件
acm rollback [AGENT]        # 恢复到最近一次 ACM 操作之前
acm run AGENT [-m REF]      # 一次性启动，不写任何文件（acm AGENT 为简写）
acm prune --keep N          # 显式清理历史（baseline 永不清理）
全局：--dry-run  --force  --yes  --verbose  --show-secrets  --no-color
```

### 4.3 语义不变量

1. **漂移没有自动修复路径**：写入遇外部漂移默认阻断；`--force`，或在交互式下明确选择"覆盖 / 不再管理 / 放弃"之一。漂移明细与其他输出一样默认掩码。
2. **目录变化显式暴露**：网关目录变化使相关 Agent 变为 `OUT_OF_SYNC`，从不自动应用。
3. **首次接管须确认**：首次写入某 Agent、把不在受管集合中的 Agent 重新纳入，或出现新的受管键时，先展示变更并确认（非交互须 `--yes`）。
3a. **受管集合由用户选择**（类似 `npx skills` 选择安装目标）：`use` / `apply` 不点名时，交互式列出本机检测到的 Agent（未检测到的不列），受管的默认勾选、其余默认不勾选；取消勾选 = 不再管理（文件保持原样）。非交互时只处理受管集合（从未选择过时默认全部检测到的 Agent）。点名 Agent = 显式纳入。不在集合中的 Agent 一律跳过，绝不静默写入。
4. **`use` 与 `apply` 不混淆**：use 改变意图并收敛；apply 只收敛。`use` 只在至少一个 Agent 投影成功（写入或已一致）后才切换激活 profile。
5. **投影损失显式告警**：目标 Agent 无法表达的设置必须在 stderr 聚合告警，不得静默丢弃（含：单端点 Agent 无法把某角色发往另一 provider）。在写入或预览时显示；无改动的重复运行不重复刷屏（`--verbose` 始终显示）。
6. **批处理独立性**：按 Agent 独立执行，一个阻断不回滚其他 Agent 的成功，最终退出码取最高严重级；同一 Agent 的多个文件视为一个单元，中途失败自动退回。
7. **恢复本身是一次写入**：任何恢复都有写前写后版本，因此可再撤销。
8. **退出码**：0 成功 / no-op；1 配置错误；2 安全阻断（漂移、写锁、白名单、校验失败）；3 I/O 失败；4 未找到；130 SIGINT。正常输出走 stdout，错误与告警走 stderr。
9. **成功路径硬标准**：已有 VMR 的用户，装好后 ≤ 3 条命令（`init`、`use`，及一次确认）让本机所有受支持 Agent 指向它；`restore --baseline` 回到接管前。

## 5. 适配器与支持范围

- 每个 Agent（或家族）一个源码内置模块；`plan` 为纯函数；金样 fixtures 门禁；不做动态加载。
- **梯队由代码路径决定**：
  - **T1**：拥有独立代码路径的 Agent（含家族族长）——必须真机实测。
  - **T2**：与某 T1 族长共用同一代码路径、只差参数的家族成员——只做金样，不做真机实测，按反馈调整，`status` 标注 `experimental`。判定规则：实现成员需要改动族长的映射逻辑（而不只是加参数）→ 它不是 T2。
  - **T3**：不内建。T3 候选需要独立代码路径，有真实需求时晋升 T1。
- 具体名单、配置位置与键值规则：`docs/ACM_Agent_Support_Matrix_opus-5.5.md`（唯一集中处）。
- 触发项：连续 90 天内 ≥ 3 个独立用户请求同一类我们不打算内建的 Agent，且无人提交源码 PR → 才考虑"本地、纯数据的自定义描述文件"（只能声明 Agent 自身目录下的一个配置文件、格式、模型键、base_url 键、key 引用键；首次使用展示将写入的路径与键并确认；不执行代码、不联网）。远端分发不在考虑范围。

## 6. 质量原则

1. **格式层先于适配器**：每种格式的 round-trip 保真测试先于任何适配器交付；任何实现必须通过同一套通用测试。
2. **金样回归**：每适配器配真实感 fixtures，三步断言——正确写入 / 非受管内容无损 / 恢复后 Agent 期间写入的状态存活；fixtures 同时是上游 schema 漂移的哨兵。
3. **故障注入**：白名单越界、多文件中途失败、提交间隙 SIGKILL、外部并发篡改、`${ENV}` 缺失、锁竞争、历史末行截断、版本对象缺失或损坏——每个安全机制有负面测试。
4. **真机实测（T1）**：每次发版，用真实 Agent 二进制在隔离环境中验证"投影后请求真的到了期望端点、带期望模型名"；T2 不做。
5. 测试在隔离 HOME 中运行，绝不读写真实用户文件。

## 7. 路线与触发表

0.4.0 范围：`init`、`status`、`use`、`apply`、`history`、`restore`、`rollback`、`run`、`prune`；T1 六个 + T2 四个；格式 JSON / JSONC / JSON5 / TOML / YAML。

触发式（不预防性实现）：

| 能力 | 触发条件 |
|---|---|
| `doctor` | 真实故障无法用 `status` 与报错信息定位 |
| `bind`（Agent 级绑定不同 profile） | 出现部分 Agent 跟随全局、部分独立的真实需求 |
| `--json` / TUI | 多 Agent 管理或漂移排查出现真实重复需求 |
| 写后校验命令（适配器级） | 某 Agent 提供稳定的配置校验命令且出现"写入有效但 Agent 起不来"的真实故障 |
| T3 候选晋升 T1 | 出现真实需求；晋升即须真机实测 |
| 本地自定义 Agent 描述文件 | 见 §5 触发项 |
| 历史导出为 git 仓库 | 出现真实需求 |
